Six Optimization Phases
1

Response Cache

LRU cache (100 entries, 30min TTL). Normalizes queries (removes "please", "show me"). MD5 key for fuzzy matching.

100% savings on hit
2

Intent Classification

4 data patterns + 2 howto patterns scored locally. Zero API calls. Routes to optimal path instantly.

0 token cost
3

Genie Space Routing

Data queries → Genie Space API (free!). SQL auto-generated from natural language. Falls back to Claude if Genie fails.

100% savings when routed
4

Tiered Prompts

Ultra-slim: ~100 tokens (data fallback). Minimal: ~150 (how-to). Slim: ~400 (general). Full: ~1,200 (standard).

50-90% prompt reduction
5

History Compression

Keeps only last 1-3 messages by intent. Older messages condensed to topic summary. Eliminates redundant context.

30-70% history reduction
6

Output Limiting

Dynamic max_tokens: 1024 (data) | 2048 (how-to) | 4096 (general). Prevents unnecessarily verbose responses.

Controls output cost
